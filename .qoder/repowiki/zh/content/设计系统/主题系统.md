## 简介
fat-design 主题系统基于 CSS 自定义属性（CSS Variables）实现，提供了一套完整的主题定制和切换机制。系统通过预设的 CSS 文件定义不同主题的视觉样式，开发者可以通过引入不同的主题文件来快速切换应用的整体外观。主题系统支持多种预设主题，包括蓝色、绿色、橙色、粉色、紫色和红色等系列，同时允许开发者创建自定义主题以满足特定的设计需求。

## 主题切换机制
fat-design 主题系统通过 CSS 类名和 CSS 自定义属性的组合实现主题切换。每个主题文件定义了一个特定的 CSS 类名（如 `.fatd-theme-default` 或 `.fatd-theme-blue1`），并在该类名下定义一组 CSS 自定义属性。这些属性涵盖了颜色、间距、圆角等设计系统的核心变量。

主题切换的核心机制是通过在 HTML 根元素或特定容器上应用不同的主题类名来激活相应的主题样式。当某个主题类名被应用时，其内部定义的 CSS 自定义属性会覆盖默认值，从而改变整个应用的视觉表现。

系统提供了多个预设主题文件，位于 `libs/theme/` 目录下，包括：
- `theme-default.css`：默认主题
- `theme-blue1.css` 至 `theme-blue4.css`：蓝色系列主题
- `theme-green.css` 和 `theme-green2.css`：绿色系列主题
- `theme-orange.css`：橙色主题
- `theme-pink.css`：粉色主题
- `theme-purple.css`：紫色主题
- `theme-red.css`：红色主题

## 主题变量详解
主题系统定义了丰富的 CSS 自定义属性，涵盖了设计系统的各个方面。这些变量按照功能分类组织，主要包括品牌色、功能色、中立色、数据色、背景色、按钮色和渐变色等。

### 品牌色
品牌色是应用的主要识别色，用于突出显示重要元素：
- `--color-brand1-1`：品牌色浅色版本
- `--color-brand1-6`：品牌色常规版本
- `--color-brand1-9`：品牌色深色版本

### 功能色
功能色用于表示不同的状态和反馈：
- **成功色**：`--color-success-1` 到 `--color-success-4`，从浅到深
- **提示色**：`--color-notice-1` 到 `--color-notice-4`，从浅到深
- **警告色**：`--color-warning-1` 到 `--color-warning-4`，从浅到深
- **错误色**：`--color-error-1` 到 `--color-error-4`，从浅到深
- **帮助色**：`--color-help-1` 到 `--color-help-4`，从浅到深
- **链接色**：`--color-link-1` 到 `--color-link-3`，表示不同状态的链接

### 中立色
中立色用于界面的基础构建：
- **线条色**：`--color-line1-1` 到 `--color-line1-4`，从浅到深
- **填充色**：`--color-fill1-1` 到 `--color-fill1-4`，从浅到深
- **文字色**：`--color-text1-1` 到 `--color-text1-4`，从浅到深
- **背景色**：`--color-bg1-1` 和 `--color-bg1-2`
- **基础色**：`--color-white`、`--color-black`、`--color-transparent`

### 数据色
数据色用于数据可视化组件：
- `--color-data1-1` 到 `--color-data1-8`：八个预设的数据序列颜色

### 其他颜色
- `--color-btn1-normal`：按钮默认状态颜色
- `--color-gradient-1` 到 `--color-gradient-4`：四个预设的渐变色

这些 CSS 变量在 SCSS 文件中被引用，通过 `var()` 函数设置默认值，确保在没有主题文件加载时仍能正常显示。

## 自定义主题创建流程
创建自定义主题的完整流程如下：

### 1. 创建主题文件
在 `libs/theme/` 目录下创建新的 CSS 文件，文件名遵循 `theme-{主题名称}.css` 的命名规范。例如，创建一个名为 "sunset" 的主题，文件名为 `theme-sunset.css`。

### 2. 定义主题类名
在主题文件中定义主题的 CSS 类名，类名遵循 `.fatd-theme-{主题名称}` 的命名规范：
```css
.fatd-theme-sunset {
    /* 主题变量定义 */
}
```

### 3. 定义主题变量
在主题类名下定义所有需要覆盖的 CSS 自定义属性。建议参考 `theme-default.css` 文件，复制所有变量并修改其值以匹配新的设计需求。

```css
.fatd-theme-sunset {
    --color-brand1-1: #ffe0b2;
    --color-brand1-6: #fb8c00;
    --color-brand1-9: #e65100;
    
    --color-success-1: #e8f5e8;
    --color-success-2: #c5e1a5;
    --color-success-3: #8bc34a;
    --color-success-4: #689f38;
    
    /* 其他变量... */
}
```

### 4. 继承现有主题（可选）
可以通过继承现有主题来减少工作量。例如，基于 `theme-orange.css` 创建变体，只需修改部分变量：
```css
.fatd-theme-sunset {
    /* 继承 orange 主题的基础 */
    --color-brand1-6: #fb8c00;
    --color-warning-3: #ff9800;
    
    /* 修改其他颜色以适应日落主题 */
    --color-bg1-1: #fff3e0;
    --color-bg1-2: #fbe9e7;
    --color-text1-4: #3e2723;
}
```

### 5. 测试主题
将创建的主题文件引入到项目中，通过应用主题类名来测试视觉效果。确保所有组件在新主题下都能正确显示。

### 6. 优化和调整
根据测试结果调整颜色值，确保对比度、可访问性和整体视觉效果符合设计要求。

## 主题继承与覆盖规则
主题系统的变量继承和覆盖遵循 CSS 的层叠规则和变量继承机制。

### 变量继承机制
CSS 自定义属性具有自然的继承特性。当在某个元素上定义了 CSS 变量，该变量会自动继承到其所有子元素。主题系统利用这一特性，在根元素或容器元素上应用主题类名，使主题变量能够影响整个应用或特定区域。

### 覆盖优先级
变量的覆盖遵循以下优先级顺序（从高到低）：
1. **内联样式**：直接在元素上通过 `style` 属性定义的变量
2. **特定选择器**：具有更高特异性的 CSS 选择器定义的变量
3. **主题类名**：通过主题类名定义的变量
4. **SCSS 变量默认值**：在 SCSS 文件中通过 `var()` 函数设置的默认值

### 变量回退机制
在 SCSS 文件中，所有颜色变量都通过 `var()` 函数定义，并提供默认值：
```scss
$color-brand1-6: var(--color-brand1-6, #5263ff);
```
这种定义方式确保了：
- 如果存在同名的 CSS 变量，则使用该变量的值
- 如果不存在同名的 CSS 变量，则使用提供的默认值

这种机制使得主题系统具有良好的向后兼容性，即使没有加载任何主题文件，应用也能正常显示。

### 局部主题覆盖
可以通过在特定容器上应用不同的主题类名来实现局部主题覆盖。例如，在一个深色背景的卡片中使用浅色主题：
```html
<div class="fatd-theme-dark">
    <div class="fatd-theme-light card-content">
        <!-- 这里的内容将使用浅色主题 -->
    </div>
</div>
```

## 主题集成最佳实践
### 1. 主题文件引入
将主题 CSS 文件作为独立的样式表引入项目。建议在主样式表之后引入主题文件，以确保主题变量能够正确覆盖默认值。

### 2. 动态主题切换
实现动态主题切换功能，可以通过 JavaScript 动态添加或移除主题类名：
```javascript
function setTheme(themeName) {
    document.documentElement.className = document.documentElement.className.replace(/fatd-theme-\w+/g, '');
    if (themeName) {
        document.documentElement.classList.add(`fatd-theme-${themeName}`);
    }
}
```

### 3. 主题持久化
将用户选择的主题保存到 localStorage 或 cookie 中，以便在用户下次访问时恢复之前的主题选择：
```javascript
// 保存主题选择
localStorage.setItem('user-theme', 'blue1');

// 恢复主题选择
const savedTheme = localStorage.getItem('user-theme');
if (savedTheme) {
    setTheme(savedTheme);
}
```

### 4. 性能优化
- 将常用的主题文件预加载，减少切换时的延迟
- 使用 CSS 变量而非预处理器变量，避免生成大量重复的 CSS 规则
- 对主题文件进行压缩和合并，减少 HTTP 请求

### 5. 可访问性考虑
确保所有主题都满足 WCAG 2.1 的对比度要求，特别是文字与背景的对比度。可以使用自动化工具检查主题的可访问性。

### 6. 主题预览
在应用中提供主题预览功能，让用户在应用主题前能够预览效果。可以创建一个主题选择器组件，显示所有可用主题的缩略图。

### 7. 主题扩展
创建主题配置文件，记录每个主题的设计规范，包括颜色使用指南、适用场景等，便于团队协作和后续维护。
